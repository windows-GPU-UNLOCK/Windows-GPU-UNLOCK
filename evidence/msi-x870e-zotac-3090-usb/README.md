# MSI X870E / Zotac RTX 3090 headless USB evidence (local profile)

## Provenance and build scope

Contributor-reported results from one machine on 2026-11-02, made with a local profile
generated by `research/profile/make-profile.py` from two read-only full-shutdown probe
captures. They are not a reviewed machine profile and not a maintainer-operated hardware
test. Nothing here adds a fixed profile or permission to boot another PC with this header.

Tracked source was `fd8bbea5b1db991805ffcd7ba84e73fa7867bd8a`. No tracked source patch.
The private `profile-local.h` was generated on this machine. Clang was 20.1.8
(`x86_64-pc-windows-msvc`). The EFI hashes in [summary.json](summary.json) depend on that
header and are not expected hashes for any other machine.

`capture-evidence.json` is the unmodified `research/profile/report-evidence.py` output for
the two probe captures only. Its `windows_outcome=direct-usable` and
`boot_kind=full-shutdown` describe those read-only probe boots, which returned to Windows.
The checker leaves `unlock_proven` false. The later unlock boots were not inputs to that
tool. `windows-inventory.json` is the reviewed `tools/collect_compatibility.py` output;
`can_unlock` stays false.

## Machine

MSI X870E GAMING PLUS WIFI (MS-7E70), BIOS 1.A60 (AMI, 2026-05-29), AMD Ryzen 9 9950X.
Zotac RTX 3090 24 GiB, GA102, `10de:2204` / `19da:1613`, VBIOS `94.02.42.80.1f`, at
`0000:01:00.0`. Cross-flash history is unknown; nothing was flashed for this report.
Windows 11 Pro build 26200. NVIDIA driver 610.62 (`nvidia-smi`); WMI reports
`32.0.16.1062`.

The AMD iGPU is present (`1002:13c0` / `1462:7e70`, bus 121). The probe saw one NVIDIA
display at bus 1, one GOP, and an EDID driver open (`NoEdidDriver` false, not aggregate).
GOP mode during the probe was 1920x1080. The physical cable was not recorded. The operator
saw the headless banner on a monitor. Windows also enumerates a Remote Display Adapter;
that is not a PCI GPU.

This is the same PCI device and subsystem as the unpublished local header in confirmed-setup
#81, and a different board, BIOS, CPU and PROM hash (`2a1eb63a…`, not `a95a2b89`). Do not
reuse either header.

The nvgop figure is the profile's code-range hash. The full `IMG29.BIN` dump hash is a
different value and is recorded only in `capture-evidence.json`. Profile FWSEC metadata:
image offset `272540` (`0x4289c`), size `57856` (`0xe200`).

Host mock: 22 of 22 `test-profile.ps1` jobs matched expectations, including the EDID-driver
release replay (5733 checks). `HardwareAccess` is false. `HardwareTested` in the generated
profile JSON was left false.

## Recorded hardware runs

Route: headless wrapper and child from a FAT32 USB stick (`GU_USB_MEDIA`), chosen in the
firmware boot menu. Profile `entryLatchedSs1Full`. Power limit stayed at the stock 350 W.
Times are local (UTC+5:30).

| Run | Boot | Entry SS0 | Result |
|---|---|---|---|
| AUTO000000 / HLS000000 | full shutdown, ~19:32 | not written | Secure Boot still on. Child stopped at `stage=secure-boot`, `attempted=0`, `clean=1`. Wrapper `original-unlock-return` and `handoff-stopped` were `0x1A` (`EFI_SECURITY_VIOLATION`). GOP was already released, so the wrapper stopped on the frozen screen. Operator powered off and booted Windows Boot Manager. |
| AUTO000001 / HLS000001 | full shutdown, 19:47:06, after the operator turned Secure Boot off | `0x60065135` | `FINAL status=0 stage=transaction attempted=1 driver_release=0 clean=1`. After FLR, `SS0=0x88888888` `SS1=0x8`. Windows started directly. |
| AUTO000002 / HLS000002 | full shutdown, 20:18:10 | `0x40065135` | Same final line and selector readback. `pre-release-cold-check`, `original-unlock-return`, `full-windows-start` and `windows-preclose-verify-begin` were status 0. Windows started directly. |

The two successful cold SS0 values differ from the probe's `0x40075135`. The entry-latched
profile latches the live cold selector and then writes `SS0=0x88888888` and `SS1=0x8`.
Selected lines are in [report-excerpt.txt](report-excerpt.txt). The stick logs were not
copied into git.

The unlock does not survive shutdown, restart or sleep on this board. The 20:18 boot was a
new USB handoff after the machine had rebooted.

## Not established

The repository cuBLAS / PyTorch GEMM protocol was not run. This report does not measure
FP16, BF16 or TF32 tensor throughput and does not claim an application speedup.

In the 19:47 Windows session a later GPU compute workload filled most of the 24 GiB and the
machine bugchecked `0x116` with `0xC000009A` (`STATUS_INSUFFICIENT_RESOURCES`). In the 20:18
session a later workload logged `nvlddmkm` events 153 and 14 and a CUDA illegal address,
while the SM clock stayed near 780 MHz and board power stayed near 140–150 W of the 350 W
limit. Those are separate from the unlock transaction. They are not a matched before/after
measurement.

Also not established: the pre-check skip branch, BootOrder fallback, sleep and hibernate
resume, warm-restart persistence, long-term stability, and the internal-ESP route. Excluded:
PROM image, `profile-local.h`, raw probe and handle-graph logs, firmware asset binaries,
partition and disk identifiers.
